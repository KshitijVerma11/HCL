Executive Summary

Road traffic collisions represent one of the leading causes of preventable fatalities worldwide, with urban arterial corridors and national highway entry gates suffering acute vulnerability. In the National Capital Territory (NCT) of Delhi, official safety audits by the Ministry of Road Transport and Highways (MoRTH) and the Delhi Traffic Police designate over 55 statutory high-fatality blackspots—including Mukarba Chowk, Azadpur, Bhalswa Chowk, Kashmere Gate, AIIMS Flyover, and Ashram Chowk.

Conventional municipal road safety interventions suffer from static latency: crash records are compiled weeks or months after collisions occur, and motorists receive no hyper-local warning of sudden environmental hazards such as localized flash waterlogging, dense winter smog/fog banks, or catastrophic vehicular impacts.

This capstone project engineers an autonomous, low-cost Cyber-Physical Roadside Unit (RSU) network and centralized geospatial intelligence platform. Each RSU is powered by an Espressif ESP32 dual-core microcontroller interfacing with environmental transducers (DHT22 microclimate, FC-37 conductive surface moisture, MPU-6050 3-axis accelerometer, HC-SR04 ultrasonic distance/speed sensor, and LDR ambient luminosity module). The firmware executes edge-side rolling-average noise filtering and an autonomous hazard classification matrix, actuating local optical and acoustic warnings (SSD1306 OLED advisory display, high-power RGB hazard strobe, and piezo siren) in under 32 milliseconds—completely independent of cloud connectivity.

Telemetry is streamed over lightweight MQTT (HiveMQ QoS 1) and HTTP REST to a hardened, zero-dependency Node.js 22 LTS central server. The platform cross-references incoming telemetry against 16,000 georeferenced incident rows, clusters hazards using Haversine geodetic distance, and presents a minimal, mountain-twilight dark dashboard with Progressive Web App (PWA) offline mobile installation.

Key Deliverables Achieved: Complete C++ ESP32 firmware, PlatformIO configuration, zero-dependency Node.js server, 55 official statutory blackspots mapped, ₹2,830 INR unit BOM cost, and 28 / 28 automated tests passing (100% pass rate).

Chapter 1: Problem Definition & Objectives

1.1 Background & Industry Motivation

Arterial highways entering Delhi NCR (such as NH-44, Grand Trunk Road, and Outer Ring Road) experience rapid microclimatic variations. A dense fog bank may reduce visibility to less than 50 meters near Swaroop Nagar while central New Delhi remains clear. When vehicles travel at 60–80 km/h, human driver reaction time (~1.5 seconds) is insufficient to prevent catastrophic rear-end pile-ups without automated roadside hazard warnings.

1.2 Core Problem Statement

How can we engineer an autonomous, low-cost, edge-intelligent Roadside Unit (RSU) network and centralized geospatial telemetry platform that detects localized environmental road hazards and crash impacts in real time, publishes synchronized telemetry over lightweight IoT protocols (MQTT/HTTP), and provides instant visual alerts to approaching motorists and municipal emergency services?

Chapter 2: Software Requirements Specification (SRS)

2.1 Functional Requirements (FR)

  • FR-01 (Multi-Sensor Ingestion): The ESP32 firmware samples temperature, humidity, surface moisture, vehicle distance, and 3-axis vibration every 1,000 milliseconds.
  • FR-02 (Edge Noise Filtering): The firmware applies a 5-sample rolling average to sensor values to eliminate transient electrical noise before anomaly evaluation.
  • FR-03 (Autonomous Edge Hazard Detection): The RSU independently evaluates physical thresholds: Crash impact (|a| > 3.5g), Waterlogging (>80% wetness), and Fog bank (>92% RH, visibility < 150m).
  • FR-04 (Sub-100ms Roadside Actuation): Upon detecting an anomaly, the RSU triggers the roadside RGB strobe (4Hz), active buzzer, and OLED hazard text within ≤ 100 ms.
  • FR-05 (MQTT Telemetry Transmission): The RSU formats sensor telemetry as JSON and publishes to topic delhi/rsu/{node_id}/telemetry over MQTT QoS 1 every 4 seconds.
  • FR-06 (Central Telemetry REST Endpoint): The server provides GET /api/iot/telemetry and POST /api/iot/simulate-anomaly returning live status for all deployed RSUs.
  • FR-07 (Official Blackspot Spatial Clustering): The system maps incidents and telemetry to the 55 statutory Delhi Traffic Police blackspots within a 500m geodetic radius using Haversine calculation.
  • FR-08 (Deterministic Corridor Risk Scoring): The ML engine calculates a composite risk score [0, 100] based on road geometry, surface condition, lighting, traffic speed delta, and live RSU telemetry.
  • FR-09 (Responsive Twilight Dark UI): The frontend presents an accessible interface featuring real-time Leaflet map rendering, CARTO dark tiles, 1-click scenario simulation, and collapsible telemetry feeds.
  • FR-10 (Offline PWA Installation): The web application provides a valid Web App Manifest (manifest.json) allowing direct installation onto mobile devices.

2.2 Non-Functional Requirements (NFR)

  • NFR-01 (Performance): Server API response time < 25 ms; client rendering at 60 FPS; edge actuation < 100 ms.
  • NFR-02 (Reliability & Fault Tolerance): 24/7 continuous operation supported by 18650 Li-ion battery backup and 5V 6W solar harvesting; autonomous local actuation during network dropouts.
  • NFR-03 (Security): Content Security Policy (CSP), sliding-window rate limiting (120 req/min), anti-path traversal, zero hardcoded secrets.
  • NFR-04 (Maintainability): Zero external npm runtime dependencies; clean C++ modular firmware compatible with Arduino and PlatformIO.

Chapter 3: System Architecture & Technical Design

The platform implements a four-tier cyber-physical architecture:

  1. Tier 1: Hardware Edge (RSU): ESP32 dual-core microcontroller (FreeRTOS) with multi-sensor array and optical/audible actuators.
  2. Tier 2: Transport Layer: Dual-protocol communication via MQTT (HiveMQ Cloud Broker, QoS 1) and native HTTP/1.1 REST fallback over 802.11 b/g/n Wi-Fi / GSM cellular bridge.
  3. Tier 3: Central Processing Engine: Hardened Node.js 22 LTS server housing Geospatial Cluster Engine (55 statutory blackspots) and deterministic Multi-Factor Risk Engine.
  4. Tier 4: Presentation & Operations: Responsive Mountain Twilight dashboard with Leaflet CARTO dark basemaps, 1-click scenarios, and PWA mobile installation.

4.2 Power Budget & Solar Autonomy Calculation

  • Daily Power Consumption: 140mA average current at 5V = 0.70W × 24h = 16.8 Watt-hours (Wh).
  • Battery Storage: 2× 18650 cells (5200mAh @ 3.7V) = 19.24 Wh (yielding 22 hours autonomous reserve without sunlight).
  • Solar Generation: 5V 6W panel yields 17.85 Wh/day at 3.5 peak sun hours > 16.8 Wh/day consumption, ensuring perpetual off-grid operation.
